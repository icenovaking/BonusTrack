## Context

本提案依本次討論：儲存卡片按鈕留在表單原位，不跟著畫面吸附；首頁牌卡取消底部重複入口提示。現有 CardForm 同時服務新增與設定頁，需避免共用樣式擴大影響。CodeGraph 已確認此工作區沒有索引，採直接讀取相關來源；實作前重新檢查索引狀態，存在索引時先執行影響分析。

## Goals / Non-Goals

**Goals:**

- 卡片設定的儲存區隨表單正常捲動。
- 使用中與已封存牌卡取消重複提示，保留整卡導覽。

**Non-Goals:**

- 不改新增卡片、消費與活動表單的定位規則，也不更動詳情頁 .mobile-action。
- 不改資料模型、計算、封存／恢復／刪除語意、儲存驗證或路由。
- 不移除無活動提示、標題箭頭、輔助閱讀描述或調整其他文案。

## Decisions

### 卡片設定專用正常文件流

在 CardForm 的現有卡片狀態加入專用樣式標記，僅覆寫其 .form-actions 為 position: static，維持其位於 form 內。手機 sticky 的共用規則保留給原本用途。相較全面取消 .form-actions 吸附，專用覆寫可限制影響；不使用 fixed，不搬移或複製提交按鈕。

### 移除牌卡底部重複入口

Home 移除 .card-link 整個容器及其中箭頭，保留 .card-heading 的 arrow 圖示、RouterLink 的目的地、aria-label 與 aria-describedby。僅在確認 .card-link 沒有其他使用點後清除其專用 CSS；不以隱藏樣式留下空白列。

## Implementation Contract

- 範圍內：現有卡片設定頁儲存區定位、首頁兩種清單的牌卡底部提示移除及針對性瀏覽器驗收。
- 範圍外：新增卡片定位、其他表單與詳情頁操作列、資料層與全站重設計。
- 使用者在短視窗捲動設定頁時，儲存區與表單內容一起移動，可捲出畫面；卡片管理保持在表單之後且不被儲存區覆蓋。可用鍵盤操作儲存，成功後返回同張卡片明細並保留儲存資料。
- 導覽介面維持 /cards/:cardId，牌卡仍是可聚焦的連結；使用中與已封存、有活動與無活動的牌卡均無「查看紀錄 / 新增消費」及底部箭頭，標題箭頭仍在。點擊牌卡內容區與鍵盤 Enter 均進入正確明細。
- 儲存錯誤仍使用表單 alert，保留草稿並可重試；沿用 busy 停用按鈕與管理操作，不增加新的錯誤或儲存路徑。
- 在 tests/e2e/card-settings.spec.ts 驗收靜態定位與實際捲動前後位置變化；使用足以產生實際捲動的視窗高度，讀取實際 scrollY，不能只斷言 CSS。建議驗收尺寸為 390×500（手機）、1280×500（桌面），並檢查 320px 窄版無水平溢出；尺寸為驗收設定而非量測結果。
- 在 tests/e2e/home-card-entry.spec.ts 驗收提示列不存在、標題箭頭存在、連結可聚焦與點擊／Enter 導覽；建立使用中／已封存、有／無活動的資料案例。
- 執行 npm run typecheck、npm run build、npm run test:e2e -- tests/e2e/card-settings.spec.ts tests/e2e/home-card-entry.spec.ts；瀏覽器必須連至此工作區的新建置，若重用既有 preview，先確認來源。另以手機觸控模式確認整張牌卡可進入明細。未執行的檢查須明列。

## Risks / Trade-offs

- 共用 CardForm 導致新增頁定位也變動 → 依 existing 狀態限制樣式，回歸新增卡片流程及原定位規則。
- 短頁面沒有捲動而產生假通過 → 使用短視窗並先確認實際 scrollY 有增加，再比對儲存區移動量與表單內容移動量。
- 移除提示降低導覽辨識 → 保留標題箭頭、完整連結、焦點樣式與輔助閱讀資訊。
- 回復方式為還原此次模板與樣式修改；無資料遷移需求。
