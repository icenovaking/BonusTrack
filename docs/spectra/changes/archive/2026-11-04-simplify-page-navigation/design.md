## Goals / Non-Goals

**Goals:**

- 在所有既有內頁及找不到卡片畫面提供一致、可操作的標題同列返回入口。
- 減少冗長導讀、全站頁尾與重複狀態，保留完成操作所需的資訊。
- 將現有修改對照規格補齊跨頁、縮放及離線驗證，明確記錄環境限制。

**Non-Goals:**

- 不更動額度計算、資料模型、IndexedDB、備份格式、路由結構或服務工作者實作。
- 不移除頂部品牌、備份入口、必要警告、表單規則、卡片識別或既有管理功能。
- 不新增返回歷史堆疊邏輯、UI 套件或獨立導覽架構；不部署、不提交其他工作樹修改。

## Decisions

### 共用標題列與既有返回目的地

採共用 CSS 類別並保留 RouterLink 的明確目的地，避免 browser.back 導向站外或不同期別。title-row 左側 h1 可縮小並換行，右側 back-link 不縮小、不拆字；不使用絕對定位，以免長標題重疊。卡片設定放在詳情標題列下方，不插入返回與標題之間。返回對齊新增活動的控制項右邊界，兩者保留同樣的按鈕內距。

替代方案是逐頁絕對定位或新增標題元件；前者不利文字放大，後者在目前相同 CSS 即能表達需求時增加元件介面，均不採用。

### 精簡文案並保留必要資訊

圖示配短標籤，返回使用「我的卡片／返回卡片」，首頁盾牌提示使用「定期備份」。三至四字是操作與狀態的優先方向，不是所有文字的硬性限制。移除規格列出的導讀及詳情空狀態重複說明；保留使用者輸入、卡名、封存狀態、欄位規則、錯誤、換卡提醒與還原警告。維持頂部品牌與備份入口。

不採純圖示導覽，避免目的地不明；不將警告硬縮為四字，避免遺失還原後果。

### 離線狀態集中於備份頁

App 移除 footer 及僅供 footer 使用的狀態綁定與 CSS；Settings 沿用 src/pwa.ts 的 offlineReady 與 registrationError，呈現準備中、成功或失敗訊息，不推導假的成功狀態。離線行為維持不變，測試不得繼續等待已移除的 footer。

### 跨頁驗證與設計索引同步

沿用既有 Playwright 及 Vitest，不增加測試框架。跨頁返回測試集中於 tests/e2e/layout.spec.ts，首頁提示沿用 tests/e2e/home-card-entry.spec.ts，離線與還原沿用 tests/e2e/storage.spec.ts。根據實際呈現維護 DESIGN.md 及 .impeccable/design.json，測試結果寫入 docs/verification/simplify-page-navigation.md。只有驗證完成的工作才勾選 tasks。

## Implementation Contract

- 範圍內：頁面標題與返回配置、既有目的地及未儲存離開確認、頁尾移除、指定文案精簡、備份頁離線狀態、設計文件、對應回歸驗證。
- 範圍外：銀行優惠規則、金額或期別運算、持久化與備份結構、服務工作者快取策略、重新設計頂部導覽、部署及 Git 提交。
- 目的地：卡片詳情、卡片新增、資料與備份、找不到卡片畫面回到 /；卡片設定、活動與消費新增／編輯回到 /cards/:cardId。保留 src/composables/form.ts 的離開確認；取消不導頁、不清除草稿，確認離開不寫入草稿。
- 共用版面驗收目標：在 320、390、768、1280 CSS px 與各寬度的 200% 文字縮放檢查內頁、長卡名及缺失卡片。上述數字是既有規格與本次明定的驗收輸入，不是效能估計。使用 boundingBox 比較標題與返回垂直中心、卡片詳情返回與新增活動右邊界；誤差最多 1 CSS px 是測試允許的次像素誤差，不是產品留白。
- 行為驗收：返回可用滑鼠、觸控及鍵盤操作；保有焦點外框與可讀名稱；長標題完整換行，沒有全頁橫向捲動、重疊或返回標籤拆行。活動、消費、卡片建立及管理動作仍可操作。
- 離線與警告驗收：準備成功只在設定頁顯示「離線可用」；失敗呈現重試訊息，不宣稱成功；備份還原前仍能看見全資料取代及不合併警告，且必須明確確認。完成快取後離線新增消費、重開、匯出與確認匯入仍通過。
- 驗證命令：npm run build；npm run test -- --run；npm run test:e2e -- tests/e2e/layout.spec.ts tests/e2e/home-card-entry.spec.ts tests/e2e/storage.spec.ts；通過後執行 npm run test:e2e 作整體回歸。人工檢查手機畫面與放大文字截圖，將結果、時間、命令及未完成項記錄至驗證文件。
- 失敗處理：測試斷言失敗先定位行為；資源不足、瀏覽器無法啟動或逾時記為未完成，保留具體錯誤，停止並行啟動瀏覽器，待資源可用再重試，不改弱斷言或宣稱通過。缺少目標卡片時保留可理解的錯誤畫面與回首頁入口，不建立新卡片。
- 導入次序：先確認工作樹既有共用樣式，再逐頁核對並補齊，最後清除舊頁尾引用。現有工作樹已包含這些修改時直接驗證，不重複改寫或回退其他內容。若驗證發現差異，只修正本變更所需部分。
- 回復方式：針對本變更的差異還原版面、文案與測試，保留原始資料及無關工作；不使用整個工作樹重設。

## Risks / Trade-offs

- 長卡名與放大文字壓縮標題寬度 → 允許標題換行，返回不拆行，跨頁驗證無重疊與橫向捲動。
- 精簡文字可能弱化資料風險提示 → 明確保留必要規則、取代警告及離開確認，不套用四字上限。
- 頁尾移除後舊測試等待不存在的訊息 → 將離線狀態斷言集中於備份頁，並實測離線操作。
- 先前環境資源不足 → 單一瀏覽器 worker 執行驗證，環境失敗保留為待驗證，與程式失敗分開記錄。
