## Context

此專案目前僅有 Spectra 與工具設定，沒有既有應用或能力規格；.codegraph/ 不存在，依專案規則不執行索引或影響分析。使用者以同一支手機在外出、出國時記錄已發生的消費，需快速知道各加碼活動還能刷多少。所有利率與上限由使用者輸入，熊本熊卡數值僅為需求範例，不代表經查證的現行優惠。沒有視覺稿或 .dc.html，因此沒有外部視覺來源需要快取。

## Goals / Non-Goals

**Goals:**

- 範圍內：Vue 手機優先 RWD、多卡多活動、日期歸期、消費維護、額度扣減、本機保存、JSON 備份、離線 PWA、繁體中文簡約介面。
- 首頁選卡、卡片內新增消費，持久化成功後首頁與內頁同時更新；保留歷史期別並可查看。
- 剩餘金額由原始紀錄推導，建立可重現的金額、日期與儲存失敗驗證。

**Non-Goals:**

- 範圍外：C#、Web API、伺服器資料庫、登入、跨裝置同步、銀行串接、即時優惠查詢、外幣換算、刷卡前模擬、自動推薦最佳卡、回饋金使用量計算、活動疊加、銀行取整規則、退款功能、活動自動判斷。
- 不收集完整卡號、有效期限或安全碼。卡片只是使用者自訂名稱。
- 本輪不實作、不安裝、不部署、不修改 .codex/。

## Decisions

### Vue 應用基礎與功能分工

採 Vue、TypeScript、Vite、Vue Router。畫面層負責輸入與呈現；src/domain/ 的純函式統一處理期別與額度；src/data/ 的 IndexedDB 存取集中負責交易與備份。採單一應用狀態保存載入結果，以共用衍生計算更新首頁與內頁。相比加入 C# 或通用多後端儲存框架，此方案符合單裝置需求；只有 IndexedDB 一個正式儲存來源，不設計未使用的伺服器轉接器。

### 額度計算與輸入驗證

金額在儲存及計算時使用安全整數分；輸入最多兩位小數，禁止非有限值、負數、超出安全整數範圍與非數字。消費須大於零；回饋上限允許零，加碼百分比須大於零且不超過 100，最多兩位小數，內部以百分之一百分點的整數保存。可刷上限以整數有理數運算向下取整至整元，再轉為分；例如上限 500 元、加碼 6% 得 8333 元，不先計算任何已用回饋金。

remainingMinor = max(0, limitMinor - sum(同活動、同所屬期別消費的 amountMinor))。畫面金額有小數時顯示至分，否則顯示整數。未選活動的紀錄不扣任何額度。超額紀錄完整保存，剩餘夾至零並以文字提醒下一筆換卡。禁止將剩餘金額另存為可變欄位，避免刪改或重試造成重複扣款。

### 期別與歷史歸屬

每張卡選日曆月或自訂結帳日（1 至 31），其所有活動共用該週期。日曆月為當月第一日至最後一日；結帳日包含在結束期，翌日開始下一期，短月份以最後一天替代。內部以 YYYY-MM-DD 日期字串及年月日期運算，不以 UTC 時戳切日；今天依手機當地日期取值，避免出國時歷史日期自行改變。

期別用結束日期識別。預設由消費日期推導；手動調整時可選該卡由消費日期推導期別的前一期、當期或下一期，保存 overridePeriodEnd，允許恢復自動歸期。首頁顯示今天所在期，內頁可查看已有紀錄的歷史期；新一期沒有消費時自然呈現完整額度，不清除舊資料。日期限今天或之前，因為第一版只記已發生消費。

卡片名稱與活動名稱可修改。為避免悄悄改寫歷史，已有消費的卡片鎖定週期設定，已有消費的活動鎖定上限及百分比；需改規則時先封存舊活動並新增活動，封存不隱藏歷史。沒有紀錄的卡片與活動允許修改或刪除；有紀錄的卡片僅允許封存，不能直接刪除。封存項目保留在歷史入口，不允許新增或移入消費；刪改既有消費仍可用。這是本版簡化方案，捨棄規則生效日與完整版本管理。

### IndexedDB 與原子備份

資料表為 cards、activities、transactions、meta；每次新增、修改、刪除或匯入用 IndexedDB 交易提交，成功後才更新可見狀態。資料存取層對外提供 load、saveCard、saveActivity、saveTransaction、deleteTransaction、exportBackup、replaceFromBackup 等操作及結構化錯誤。寫入失敗保留表單並顯示可重試訊息，不偽造成功、不清空資料；首次讀取失敗顯示重試與備份說明，不以空資料覆寫。

JSON 備份包含 schemaVersion、exportedAt、cards、activities、transactions。匯入採完整取代而非合併，先驗證版本、必要欄位、唯一 ID、外鍵、日期、期別調整有效性、金額與名稱；匯入時不以今天限制既有消費日期，以支援旅行時區改變。驗證通過後顯示筆數摘要並要求使用者明確確認取代；取消或任何錯誤都保留原資料。重新匯入同一份備份不會加倍消費。不把 IndexedDB 或 Service Worker 快取當成備份。

### PWA 離線與更新

使用 Vite PWA 整合生成 manifest 與 Service Worker，快取同源應用殼、必要腳本、樣式與圖示，不依賴外部 CDN 或網路字型。首次成功載入且離線資源快取完成後，顯示可離線使用狀態；未快取前不保證離線可開啟。手機支援的平台可加入主畫面，未提供安裝事件時以對應瀏覽器操作說明替代，不以安裝作為記帳前提。

靜態 HTTPS 主機部署，採 hash 路由以避免重新整理子頁需要伺服器 rewrite。更新版本以提示方式啟用，表單有未保存資料時不強制重載；更新不得清除 IndexedDB。首版離線以本機交易運作，不需要同步佇列。

### impeccable 簡約 RWD 與操作可及性

實作前使用 impeccable 的 context 與適用設計流程，在提案既定範圍內落實手機任務介面。風格固定為淺色背景、深色文字、單一強調色、留白與清楚字級，不引入行銷區塊、裝飾性大圖或回饋金圖表。卡片內大字呈現各活動剩餘金額，上限及期別次要；沒有活動時提示新增活動。

手機首頁單欄；較寬畫面依內容容納多欄，卡片不互相比較或加總不同活動額度。內頁先額度後紀錄，新增消費使用獨立頁面，固定下方主要按鈕須避開手機安全區與鍵盤。多活動時新增消費初始要求選擇活動或明確選不適用；只有一個可用活動時預選；選項包含加碼百分比以協助辨識。

以下數值為設計驗收目標而非已測量結果：支援 320 CSS px 起不產生整頁水平捲動；主要觸控目標至少 44 CSS px；表單字體至少 16 CSS px。以 320、390、768、1280 CSS px 及 200% 文字縮放驗證內容不截斷、按鈕可用。以鍵盤操作、可見焦點、欄位標籤、成功狀態播報及非純顏色錯誤提示驗收。長卡名、零額度、空資料、儲存失敗、未快取與封存狀態均有明確文案。

## Implementation Contract

- Card: id、name、cycleMode(calendar-month/billing-day)、closingDay、archived；Activity: id、cardId、name、rewardCapMinor、bonusRateBasisPoints、archived；Transaction: id、cardId、activityId 或 null、spentOn、amountMinor、note、overridePeriodEnd 或 null。ID 使用本機唯一字串，名稱去頭尾空白後不得為空，僅以文字渲染。
- domain 公開 deriveSpendLimit、resolvePeriod、calculateRemaining 純函式；相同輸入須產生相同結果。資料層驗證消費活動屬於同張卡、覆寫期別合法及所有加總不超過安全整數，不信任表單或備份資料。
- 使用者首頁選卡，新增已發生消費，儲存成功才切回該卡本期紀錄並提示成功；若儲存至歷史期或下一期，切至實際所屬期並顯示期別，首頁仍顯示今天所在期。不連續按儲存產生重複紀錄。
- 第一筆消費建立後鎖定相關規則；修改、刪除、移動期別都從紀錄重新計算原期與目標期。刪除需確認，可取消；新一期不刪舊資料。封存行為遵循 Decisions。
- Vitest 驗證金額取整、小數、零值、超額、活動隔離、月底閏年與移期；IndexedDB 整合測試驗證重開持久化、失敗原子性及備份取代。瀏覽器驗證建立卡片到儲存消費、重新整理、離線重開及 RWD 操作。
- 驗收固定需求範例：500 元 / 6% 的可刷上限為 8333 元；消費 100 元後為 8233 元；再消費 1000 元為 7233 元；累計超額顯示零，消費不截短。範例數字是測試輸入與公式結果，不是銀行承諾。
- 實作範圍與排除事項以 Goals / Non-Goals 為準。任何真實手機無法驗證的安裝或離線行為，交付時單獨註明，不以桌面模擬宣稱實機通過。

## Risks / Trade-offs

- [清除瀏覽器資料、換機或儲存被回收可能失去紀錄] → 提供匯出匯入與本機保存說明，適當申請持久儲存但不保證結果。
- [銀行入帳日、取整或條款與手動設定不同] → 明示僅為消費額度估算，允許編輯台幣金額與手動歸期，不顯示未經查證的優惠預設。
- [單裝置不代表永不遺失資料] → 不宣稱雲端備份；匯入前明確警告完整取代。
- [規則鎖定增加改優惠的操作] → 封存舊活動並新增，換取歷史額度不被重寫；若需要生效日版本管理，另開變更。
- [PWA 支援程度及手機鍵盤行為不同] → 提供一般瀏覽器使用路徑、完成快取再提示離線可用，驗證實機並如實記錄限制。
